# Атлас для Android

Цель продукта: отдельный нативный интерфейс и офлайн-работа всех разделов существующего сайта. Это начальный этап реализации, **не полная замена сайта**. Состав целевой версии и недостающие части перечислены в [матрице покрытия](../docs/android/coverage.md).

## Реализовано

- Kotlin, Jetpack Compose, Android 8+; сервер `https://boora.ru`.
- Вход существующей учётной записью. Пароль не сохраняется; токен зашифрован ключом Android Keystore. Резервное копирование данных приложения отключено.
- Локальные карточки техники и графики ТО в Room, поиск, отображение даты последнего обновления.
- Регистрация планового и обкаточного ТО без сети; одна неотправленная операция на машину.
- Сохраняемая очередь операций, автоматическая отправка через WorkManager при доступной сети, ручная синхронизация.
- Повтор после потери ответа с тем же operationId; HTTP 409 требует ручного разбора, 401 — повторного входа. Чужая очередь никогда не отправляется под новой учётной записью.
- Серверная поддержка идемпотентного выполнения ТО: идентификатор и хеш запроса записываются атомарно вместе с событием ТО.
- Раздел «Ремонт»: открытые/завершённые неисправности, поиск, карточка и история этапов ремонта, взятие заявки в работу.
- Запись результата ремонта без сети: описание, причина, место, дата/время, исправен/неисправен/ожидание запчастей, продолжение эксплуатации или начало простоя.
- Отдельная сохраняемая очередь ремонта с проверкой версии журнала и защитой от дублирования при потере ответа.
- При HTTP 401 автоматически открывается экран авторизации. Требование входа сохраняется после перезапуска; очередь ТО/ремонта остаётся на телефоне. Вход другим аккаунтом при необработанных записях запрещён.

Версия 0.2.0. Подробности и сценарии проверки ремонта: [repair.md](../docs/android/repair.md).

## Сборка

Нужны JDK 17+ (локально используется 21), Android SDK Platform 36 и Build Tools 36.0.0. В `local.properties` укажите `sdk.dir`; файл не хранится в Git. Gradle Wrapper проверяет SHA-256 дистрибутива.

```powershell
cd android
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка для проверки; для распространения потребуется отдельный release-ключ.

Проверено 24.10.2026: сборка APK, 9 Android unit-тестов и Android Lint прошли; ошибок Lint нет, остаются предупреждения о версиях зависимостей и стиле. На бэкенде прошли 146 модульных тестов и проверка сохранения/повторной отправки/конфликтов ТО на отдельном PostgreSQL 17. Временный контейнер и SSH-туннель после проверки удалены/закрыты.

## Совместимость сервера

Серверная поддержка офлайн-ТО и ремонта опубликована на boora.ru 26.10.2026. На старом сервере приложение сохраняет очередь и сообщает о необходимом обновлении. Отправки без защиты от повторов нет.

Новый `GET /api/maintenance-plans/sync-capabilities` возвращает `completionIdempotency: 1`. В запрос выполнения добавлено необязательное `operationId`; существующий сайт продолжает работать без него. Инициализатор добавляет nullable-колонку `request_hash` в журнал ТО.

Релиз: [20261026-1c13966](../docs/deployment/release-20261026-1c13966.md). [Скачать APK 0.2.0 для проверки](https://boora.ru/downloads/atlas-0.2.0-debug.apk). Проверены 17 Android unit-тестов, lint, сборка и установка поверх прежней версии в эмуляторе с сохранением подписи.

Для ремонта дополнительно нужны `GET /api/repair-sync`, `POST /api/repair-sync/commands`
и таблица `repair_operation_receipts` из штатного инициализатора. До обновления сервера
приложение сообщает о несовместимости и не отправляет ремонт через старый API.

## Проверка на устройстве

1. Войти тестовым пользователем на тестовом сервере/окружении; загрузить данные.
2. Включить авиарежим, перезапустить приложение: карточки остаются доступны.
3. Зарегистрировать ТО, перезапустить приложение: запись остаётся в очереди.
4. Восстановить сеть: сервер получает одну запись. Потеря ответа не создаёт повторное ТО.
5. Изменить график другим клиентом до отправки: приложение показывает конфликт и сохраняет исходное описание.
6. Отозвать сессию: очередь остаётся, требуется повторный вход тем же пользователем.

Тестовые записи нельзя создавать в производственных данных ради проверки приложения. 24.10.2026 установлен эмулятор Android 16 (API 36, Google APIs x86_64), создан AVD `Boora_API_36` с профилем Pixel 6. Проверены загрузка с WHPX, установка APK и открытие экрана входа без ошибок AndroidRuntime. Авторизованные и офлайн-сценарии на устройстве ещё не проверены.

Пользовательский SDK эмулятора: `%LOCALAPPDATA%\Android\Sdk`. Запуск — ярлык **Boora Android Emulator** на рабочем столе. Отладочный APK уже установлен на виртуальный телефон. Снимок экрана входа: `artifacts/android/emulator-login.png`.

## Архитектура

UI читает локальную базу, Repository объединяет API и очередь. Синхронизация и действия с сессией сериализуются mutex. HTTP использует только HTTPS и не следует перенаправлениям с bearer-токеном. Состояния `pending`, `conflict`, `rejected` имеют разное поведение; конфликт не превращается автоматически в запись с новой версией.

Архитектура локального источника данных и сохраняемой очереди соответствует [руководству Android offline-first](https://developer.android.com/topic/architecture/data-layer/offline-first).
