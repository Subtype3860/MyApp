# Почему тормозили «Танки»

Проверено 27.10.2026. Исходная версия для сравнения: `be7963e`. Оптимизация опубликована на boora.ru в [релизе 20261027-ba4f41a](../deployment/release-20261027-ba4f41a.md).

## Найденные причины

1. `render.js` на каждом кадре заново строил неизменяемую геометрию всей карты, создавал массив чисел и копировал его в новый Float32Array. В нагруженной сцене это 77 832 вершины и 2 801 952 байта, передаваемых в WebGL каждый кадр. После увеличения карты и числа усилений эта работа стала особенно дорогой.
2. Контуры каждого усиления состояли из 32 объёмных кубиков: 1 152 вершины на один контур. Объекты за границами экрана также строились на CPU.
3. Сетевой клиент сразу заменял позиции каждым серверным снимком. Сервер присылает их 20 раз в секунду, поэтому даже при хорошей частоте отрисовки движение было ступенчатым.
4. Таблица игроков и список усилений пересоздавались при каждом снимке, включая неизменённые значения. Одинаковая сцена в меню также рисовалась с частотой монитора.

## Изменения

- Статическая карта строится и загружается в STATIC_DRAW-буфер один раз.
- Динамическая геометрия использует повторно выделенный Float32Array и bufferSubData. GPU-буфер увеличивается только при нехватке места.
- Контуры сделаны плоскими кольцами из треугольников; динамические объекты за пределами камеры пропускаются. Геометрия препятствий и правила столкновений сохранены.
- `motion.js` сглаживает только визуальные позиции и повороты между снимками. Телепорты, смерть и возрождение отображаются без скольжения. Урон, здоровье и очки по-прежнему берутся с сервера. Движение снарядов визуально продолжается не более чем на 50 мс.
- HUD обновляется не чаще 10 раз в секунду и меняет DOM только при изменении значений. Неизменяемая сцена в меню/на паузе рисуется 4 раза в секунду вместо 60.
- После уточнения о сетевом бое на компьютере добавлен прогноз движения своего танка (`prediction.js`). Клавиши двигают локальную модель до ответа сервера; сервер возвращает номер обработанного ввода `ackSeq` и номер возрождения `spawnId`. Клиент повторяет ещё не подтверждённый ввод и плавно сверяет результат. Прогноз использует общие препятствия и не меняет здоровье, попадания, усиления или очки. При отсутствии новых снимков более 300 мс локальное движение приостанавливается. Старый API без подтверждений автоматически оставляет только сглаживание.
- Начало и завершение нажатия клавиши отправляются сразу, без ожидания очередного 50-миллисекундного интервала. Сервер отвергает повторные/устаревшие последовательности и по-прежнему рассчитывает движение с фиксированным шагом: дополнительные пакеты не увеличивают скорость танка.

## Замеры

Edge / Windows, Intel UHD Graphics 630 через ANGLE Direct3D11. Одна и та же синтетическая сцена: 8 танков, 36 усилений, 32 снаряда. После 30 прогревочных кадров измерены 120 кадров. Метрика renderMs — время JavaScript-подготовки и отправки команд, а не полное время выполнения GPU.

| Сценарий | До: медиана / p95 | После: медиана / p95 |
|---|---:|---:|
| 1440×900, DPR 1 | 16,0 / 20,1 мс | 0,8 / 1,5 мс |
| 390×844, DPR 2, CPU замедлен в 4 раза | 129,7 / 152,9 мс | 6,8 / 8,4 мс |

Динамическая передача геометрии в настольном сценарии сократилась с 2,80 до 0,52 МБ/кадр (примерно на 81%). Статическая загрузка 0,70 МБ выполняется один раз. Межкадровый интервал p95 на компьютере снизился с 25,6 до 16,9 мс. На замедленном CPU — с 154,4 до 17,1 мс. Это лабораторный результат на указанном GPU; искусственное замедление CPU не заменяет проверку на настоящем телефоне.

При проверке boora.ru общая load average была 0,61 / 0,28 / 0,17; явной перегрузки не обнаружено. Два обмена сообщением по WebSocket заняли 238 и 236 мс (без входа в арену, с заведомо недействительным ticket). Такая сетевая задержка сама по себе влияет на отзывчивость. Прогноз скрывает ожидание при управлении своим танком, но фактический сетевой обмен и подтверждение попаданий по-прежнему требуют времени.

## Воспроизведение и проверки

Запустить Vite на 127.0.0.1:5150, затем из корня проекта:

```powershell
node frontend/scripts/benchmark-tanks.mjs --baseline be7963e
node frontend/scripts/benchmark-tanks.mjs
```

Результаты и скриншоты записываются в `artifacts/tanks-performance/`. В тесте нет рабочих данных, API или внешних ресурсов.

16 сценариев `tanks-game.spec.js` / `tanks-online.spec.js` прошли, включая подбор усилений, столкновения, сетевой допуск, отзыв права, устаревшее соединение, сглаживание и прогноз без изменения серверных значений. Отдельный браузерный тест удерживает серверные координаты неподвижными и подтверждает, что нажатие D сразу сдвигает отображаемый танк; системные часы теста зафиксированы, поэтому результат не зависит от времени загрузки GPU. Все 169 серверных unit/network-тестов прошли, в том числе проверка подтверждения и защиты последовательностей. Проверено изображение арены после оптимизации.
