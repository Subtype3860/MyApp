# «Броня»: танки 3D

Анализ задержек и локальная оптимизация отрисовки: [замеры производительности](tanks-performance.md).

Игра: http://localhost:5150/games/tanks/index.html

Запуск: `npm run dev` из `frontend`. Файлы в `frontend/public/games/tanks` включаются в статическую сборку. Для Vite используйте полный адрес с `index.html`. Опубликована 27.10.2026: https://boora.ru/games/tanks/index.html. В Atlas доступна через меню «Игры → Танки 3D».

## Сетевая арена

Основной адрес теперь открывает сетевую PvP-арену до 8 зарегистрированных пользователей. Откройте «Танки 3D» в меню Atlas либо перейдите по ссылке выше после входа. Усиления и снаряды общие; здоровье, передвижение, урон, подбор и очки рассчитывает сервер. После уничтожения танк возрождается через 3 секунды. Защита после возрождения действует 3 секунды и снимается при выстреле. На арене нет общей паузы: Escape или ↩ отключают игрока; скрытие вкладки также выводит из боя.

Карта увеличена с 64×64 до 128×128: 40 зданий и баррикад вместо 6, с проходами между секторами. Общий файл `frontend/public/games/tanks/arena.json` используется клиентом и копируется при сборке/публикации API в `Games/tanks-arena.json`. Сервер и графика используют одинаковые границы и препятствия. На сетевой карте изначально 28 усилений, максимум 36; пополнение раз в 2 секунды. Тренировочная карта также расширена, усиления распределены по внешним секторам. Проверена достижимость четырёх внешних углов и начальных контейнеров.

Допуск выдаётся администратором: **Настройки → Пользователи → редактировать → «Танки — доступ к сетевой игре» → Сохранить**. Затем пользователь входит заново: существующая система отзывает старую сессию при изменении прав. Новым пользователям право `games.tanks` автоматически не назначается; существующие пользователи также не получают его при обновлении. Администраторы имеют доступ согласно общему правилу роли Atlas. Снятие права, отзыв сессии, удаление пользователя и истечение JWT отключают действующее соединение при очередной проверке (каждые 3 секунды).

`GET /api/tanks/lobby` и `POST /api/tanks/ticket` требуют действующий Bearer JWT и актуальное право из БД. Ticket одноразовый, действует 20 секунд и отправляется первым сообщением в WebSocket `/api/tanks/socket`. JWT и ticket не помещаются в URL. До проверки ticket клиент не включается в арену и не получает её состояние. Клиент передаёт направление, прицел, огонь и порядковый номер ввода; сервер не принимает клиентские координаты, здоровье или награды. Для одной учётной записи допускается одно соединение. Лимиты: 8 игроков, сообщения до 1 КБ, 60 сообщений в секунду, handshake до 5 секунд, отсутствие ввода до 10 секунд. Через 0,5 секунды без свежего ввода танк прекращает движение и стрельбу.

Сервер рассчитывает и рассылает состояние 20 раз в секунду. Медленные клиенты получают последнее состояние без бесконечной очереди. При потере связи интерфейс сообщает об отключении, прекращает отправку и очищает состояние арены; повторное подключение запускается вручную. Результаты PvP находятся в памяти процесса и сохраняются 60 секунд после выхода для переподключения; перезапуск API очищает их. Это одна арена на один экземпляр API. Для нескольких реплик нужен общий игровой сервер/распределённая маршрутизация; текущую версию следует запускать в одном экземпляре.

### Развёртывание

Нужны обновлённые API и фронтенд. Изменения схемы PostgreSQL не требуются: допуск хранится в существующем поле разрешений. В production разрешённые WebSocket Origin по умолчанию: `https://boora.ru` и `https://www.boora.ru`. Другие адреса задаются массивом `Tanks:AllowedOrigins`; локальные адреса Vite добавляются только в Development. Vite-прокси уже поддерживает WebSocket.

Для nginx добавьте Upgrade в проксируемый `/api/` или отдельный location (значение порта сверить с окружением):

```nginx
location /api/tanks/socket {
    proxy_pass http://127.0.0.1:5296;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 60s;
}
```

Никакие реальные допуски в ходе разработки и публикации не выдавались. Сетевая версия опубликована на boora.ru 27.10.2026; [отчёт о проверке и резервных копиях](../deployment/release-20261027-78eb39c.md).

## Одиночный тренировочный режим

Сохранён по адресу `/games/tanks/index.html?mode=solo`, без доступа к сетевой арене и данным других пользователей.

Управляйте зелёным танком, собирайте светящиеся контейнеры и уничтожайте пять волн противников. В каждой волне от трёх до семи танков. Камера следует за игроком; здания и границы блокируют движение и снаряды.

- WASD / стрелки — движение, мышь — поворот башни.
- Левая кнопка мыши или пробел — непрерывный огонь.
- Без мыши башня автоматически нацеливается на ближайшего противника.
- На телефоне: левый джойстик и правая кнопка огня с автоматическим прицеливанием.
- P / Escape — пауза и продолжение. При переключении вкладки игра ставится на паузу.

Подбор происходит автоматически на расстоянии до 1,5 игровой единицы. Новые контейнеры появляются раз в пять секунд и могут выпадать из противников. Повторный подбор обновляет срок усиления, разные эффекты сочетаются.

| Усиление | Эффект | Время |
|---|---|---|
| Турбодвигатель | Скорость 10,5 вместо 6 | 18 с |
| Броневой щит | Снижение входящего урона на 80% | 20 с |
| Урон ×2 | Удвоение урона снаряда | 18 с |
| Двойной залп | Два снаряда за выстрел | 18 с |
| Ремонт | +35 здоровья, максимум 100 | Сразу |

Очки: 25 за контейнер, 100 за противника, 1 000 за прохождение пяти волн. Рекорд хранится в localStorage (`bronya.best.v1`); текущий бой начинается заново после перезагрузки. При недоступности хранилища можно играть без сохранения рекорда.

## Реализация и проверки

Собственный WebGL-рендерер с перспективной камерой, освещением, объёмными моделями, частицами и прицелом. Графика строится из геометрии, внешние ресурсы и зависимости не загружаются. В тренировке игровое время останавливается на паузе; освобождение сенсорных указателей и потеря фокуса сбрасывают ввод. Производственные данные техники не используются.

`world.js` и `solo.js` — тренировка; `render.js` — WebGL; `online.js` и `network.js` — сетевой клиент. Сервер: `MyApp.API/Games/Tanks*`. При недоступном WebGL или потере контекста выводится объяснение.

Проверки: `npx playwright test tests/tanks-game.spec.js` из `frontend` (при необходимости `$env:PLAYWRIGHT_CHANNEL='msedge'`). Сценарии охватывают подбор в движении и срок действия, ремонт/щит/стены, двойной залп и урон, победу/поражение, уничтожение противника, запуск 3D и паузу, мобильный джойстик. Проверены скриншоты 1440×1000 и 390×844. Сборка Vite проходит с существующим предупреждением о размерах чанков основного приложения.

Сетевая часть: `tanks-online.spec.js` проверяет вход, 401/403/ошибки API, отображение соперников и отключение при отзыве. `TanksOnlineTests` запускает настоящий Kestrel с JWT и двумя WebSocket-клиентами на синтетическом хранилище: доступ, запрет самовыдачи права, одноразовость ticket, общая арена, отзыв допуска и сессии, недопустимые команды, вместимость и ограничения передвижения. `UserSessionRevocationTests` проверяет отсутствие допуска при регистрации и выдачу/снятие с отзывом сессии. Рабочая БД в этих тестах не используется.
