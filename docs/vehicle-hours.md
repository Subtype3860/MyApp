# Моточасы

В меню «Транспорт → Моточасы» доступны компактный ручной ввод и импорт через модальное окно. Дата показаний общая; самосвалы имеют поля ДВС № 1 и № 2, остальные машины — одно поле. Показания сохраняются отдельно по двигателям и используются в «Выходе ГТО». Значения при замене ДВС остаются отдельными данными.

## Ежедневный Excel

По умолчанию выбран формат «Excel: лист на каждую дату». XLSX до 5 МБ читается в браузере. Исходный файл не отправляется на сервер. ZIP распаковывается библиотекой [fflate](https://github.com/101arrowz/fflate), затем читаются XML-данные ячеек. Формулы не исполняются, для них нужен сохранённый результат Excel. Максимум — 366 листов, 20 МБ распакованных XML и 10 000 показаний.

1. Выберите файл и диапазон поиска (по умолчанию `A1:Z50`, не более 20 000 ячеек на лист).
2. Проверьте распознанные блоки. Заголовки техники и моточасов могут находиться в разных местах выбранного диапазона. Пробелы, переносы строк и варианты `М/ч`, `Моточасы`, `ДВС1`, `ДВС2` нормализуются. При изменении структуры можно вручную задать строку заголовков, столбец техники и столбцы двигателей каждого блока на каждом листе.
3. Нажмите «Проверить файл». На сервер отправляются только распознанные записи. Предпросмотр показывает источник (лист/ячейку), дату, бортовой номер, ДВС, итоговое показание и результат проверки.
4. Проверьте ошибки и предупреждения. Для частичного импорта нужно явно подтвердить пропуск ошибок. Все допустимые показания сохраняются одной транзакцией.

Дата берётся из имени листа, год — текущий год браузера. Лишние пробелы и знаки препинания допускаются: ` 08 . 10.. `, `08,10`, `(08.10)`, `08 — 10` и `08 10` означают 8 октября. Название должно содержать ровно два числа: день и месяц. Неверные даты (`31.02`), слитные числа (`0810`), дополнительный год или номер копии (`08.10 (2)`) показываются как проблемы. Исходное название сохраняется в источнике записи. Если разные названия означают одну дату, сервер выявляет повторные показания. Показания относятся к **08:00 местного времени площадки**, началу первой смены. В базе используются дата и `reading_time=08:00`, без разделения на смены; для каждого двигателя одна запись на дату. Старые и ручные записи сохраняют неизвестное время (`NULL`).

Техника сопоставляется только по бортовому номеру: `SET 901` → 901, `Sany 1250/91` → 91, `Caterpillar №938` → 938. Порядковый столбец «№» не используется. Неизвестные и неоднозначные номера отклоняются. Общий столбец моточасов допустим только для техники с одним двигателем; для самосвала нужны явно обозначенные двигатели.

Пустая ячейка означает простой. После сортировки по датам переносится последнее предыдущее показание того же двигателя из файла или базы, строго до импортируемой даты. Будущие показания не используются. Без предыдущего значения строка получает ошибку. Текст, отрицательное число и ошибка формулы не считаются простоем. После ошибочного показания перенос блокируется до следующего корректного явного значения.

Проверки на сервере:

- Уменьшение счётчика, конфликт с последующим сохранённым значением и дубли даты/техники/ДВС в файле отклоняются. Замена двигателя оформляется отдельно.
- Прирост более 24 м/ч за сутки между замерами требует подтверждения. Пропущенные даты не создаются автоматически.
- Уже сохранённое одинаковое показание пропускается. Другое показание за ту же дату считается конфликтом и не перезаписывается этим режимом.
- При сохранении проверка повторяется под транзакционной блокировкой таблицы показаний. Если результат отличается от предпросмотра, возвращается HTTP 409 и требуется повторная проверка. Права проверяются на обоих этапах.

API: `POST /api/vehicles/hours/daily/preview` и `/commit`. Тело — `rows` с полями `readingDate`, `garageNumber`, `engineNumber`, `engineHours`, `invalid`, `source`. Для сохранения также передаются `fingerprint` предпросмотра и `acceptWarnings`. Пустые исходные ячейки остаются `null`: сервер заново вычисляет перенос по истории.

Поле времени добавляет `DatabaseInitializer`; для ручного обновления схемы предусмотрен `scripts/migrations/20261021_daily_hours.sql`.

## Прежний формат на одну дату

В списке форматов остаётся «CSV / Excel: одна дата (прежний формат)». Он отправляет файл на сервер и использует выбранную дату ручного ввода. Его правила не изменены.

Импорт принимает CSV UTF-8 и XLSX до 5 МБ. Колонки: `garage_number`, `model`, `engine_1`, `engine_2`. Например:

```csv
garage_number;model;engine_1;engine_2
901;SANY SET 150S;875;852
94;SANY SY1250H;20511;
```

Техника определяется по точному сочетанию гаражного номера и модели без учёта регистра. Пустые ячейки двух колонок не изменяют показания. Альтернативный формат трёх колонок допускает `875/852` для самосвала, одно значение для техники с одним ДВС. Единственное число для самосвала отклоняется, чтобы не присвоить показания неверному двигателю. Старые двухколоночные XLSX с известными обозначениями техники читаются с теми же правилами.

Импорт пишет показания на выбранную дату; повторный импорт обновляет показания этого двигателя за этот день. Окно показывает число принятых показаний и ошибки по строкам. Отрицательные значения и второй ДВС у машины с одним двигателем отклоняются. Дубли конкретного ДВС пропускаются. Шаблон CSV можно скачать в окне импорта.

## Проверка изменений

Серверные тесты: `DailyHoursPlannerTests`, `VehicleHoursEngineImportTests`, `VehicleHoursAuthorizationTests`.
Браузерные: `npm run test:e2e -- tests/daily-hours-import.spec.js tests/vehicle-hours.spec.js`.
Если браузер Playwright не установлен, можно задать `PLAYWRIGHT_CHANNEL=msedge` для установленного Edge. Необязательный `HOURS_SAMPLE` указывает путь к исходному файлу для проверки 17 листов, 448 показаний и 198 пустых ячеек без записи в базу.
