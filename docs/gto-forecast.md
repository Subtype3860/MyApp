# Выход ГТО: первая версия формы

Раздел «Отчёты → Выход ГТО» формирует прогноз готовности всего активного парка, сгруппированного по справочнику group_car (поле vehicle.groupName в API). Дату и смену выбирает механик. По умолчанию предлагается следующая смена относительно существующего правила приложения: до 12:00 исходная дата — предыдущий день и исходная смена — 2, после — текущий день и смена — 1. После исходной смены 2 предлагается смена 1 следующего дня; после смены 1 — смена 2 той же даты.

Данные текущего ремонта берутся из `/api/vehicles/repair-journal`: состояние техники, нерешённые неисправности и даты начала простоя. Завершённые работы со статусом repaired закрывают соответствующую неисправность. API также возвращает в hours последнее зарегистрированное показание моточасов каждой машины (дата, значение и примечание), а не всю историю показаний. Архивная техника в прогноз не включается.

В форме показана только активная техника с текущим operationalState = stopped, включая ожидание запчастей при остановленной эксплуатации. Для неё механик выбирает состояние к смене: «Исправен» или «Неисправен». По умолчанию оно соответствует текущему состоянию. В PDF сохраняется весь активный парк: для техники вне формы состояние подставляется из ремонта, без применения старых черновиков. В работе с неисправностью означает «Неисправен». В итог выхода включается состояние «Исправен». Прежние значения черновика автоматически преобразуются в два состояния. Примечание механика, плановый выход (дата/смена либо условие), КТГ, вид ТО и состояние кондиционирования/отопления — необязательные поля. КТГ вводится вручную в диапазоне 0–100%; расчёт КТГ из истории не добавлен.

Форма доступна для редактирования механикам, старшим механикам и администраторам по признаку canManage существующего API. Остальные пользователи с правом просмотра раздела видят исходные данные. Прогноз не изменяет ремонты и не создаёт работ.

PDF в альбомной ориентации содержит поля исходного образца, дополнительную колонку прогноза, итоги по группам и общую сводку выхода. Поиск техники в форме не меняет состав PDF: экспортируется весь парк. Длинные тексты переносятся на новые страницы.

На первом этапе черновик прогнозных полей хранится в localStorage текущего браузера отдельно по пользователю, без даты и смены. При обновлении данных ремонта ручные поля сохраняются, поэтому перед каждой выгрузкой их необходимо проверить. Черновик не синхронизируется между устройствами; серверное сохранение, архив прогнозов, утверждение и отправка пока не добавлены. PDF можно скачать для передачи и хранения.

В «Неисправность/примечание» включаются все незакрытые заявки на закупку запчастей соответствующей машины (CompletedDate = NULL), с номером, датой, описанием и требуемыми запчастями. API возвращает их в partsRequests на уровне журнала, поэтому заявки без ремонтных работ также учитываются. Дубли в работах исключаются по идентификатору. Закрытые заявки не выводятся.

Оформление примечаний: сначала номер/дата и текст незакрытой заявки на закупку, затем связанная с её defectId неисправность. Заявки на ремонт выводятся жирным с горизонтальным разделителем по нижнему краю текста, без вертикального отступа. Нерешённые неисправности без закупочных заявок также выводятся отдельно. «Неисправен» в PDF выделяется красным и жирным. Для настоящего жирного начертания встроен Liberation Sans Bold; лицензия расположена рядом с файлом шрифта.

Причина простоя после закупочной заявки берётся из description последнего этапа ремонта со статусом awaiting_parts («Отсутствие ЗЧ») для того же defectId. Первоначальные symptoms/failureReason ремонтной заявки в этом блоке не используются. Более поздние этапы с другими статусами не заменяют причину ожидания запчастей. Если подходящий этап отсутствует, остаётся только текст закупочной заявки.

Текст закупочной заявки и описание этапа ожидания запчастей теперь выводятся одним абзацем через дефис. Описание этапа — курсивом. Горизонтальные разделители примечаний удалены. При нехватке ширины текст переносится внутри ячейки PDF.

Компоновка PDF уплотнена. Перед выводом сводки измеряется высота всего блока, включая переносы названий групп: при нехватке места он переносится целиком на новую страницу без шапки таблицы. Обычные строки таблицы удерживаются вместе; слишком длинные строки допускают продолжение. Для размещения всего парка на одном листе автоматически выбирается альбомный либо книжный A4. Если объём примечаний превышает вместимость одного листа, сохраняется многостраничный отчёт со сводкой без разрыва. Проверочный отчёт с 39 машинами размещается на одном A4.

## Постоянные настройки

Организация и участок сохраняются в `gto_user_settings` для текущего авторизованного пользователя. Состояние кондиционирования/отопления сохраняется в `gto_vehicle_settings` по ID техники. Плановый выход хранится в `gto_defect_settings` по ID открытой ремонтной заявки; для поля машины он сохраняется за текущими открытыми заявками этой машины. После закрытия соответствующей заявки значение перестаёт использоваться и не переносится на новый ремонт. Поля сохраняются автоматически при изменении (для текста — при выходе из поля). API проверяет права механика/старшего механика/администратора и принадлежность ремонтных заявок технике, отклоняя устаревший состав заявок.

`GET /api/gto-settings` возвращает собственные пользовательские настройки и технические настройки. `PUT /api/gto-settings/user` изменяет только настройки текущего пользователя. `PUT /api/gto-settings/vehicles/{id}` сохраняет климат и плановый выход с проверкой списка открытых defectIds. Таблицы создаются DatabaseInitializer. Существующие настройки из локального черновика переносятся в базу один раз при первом открытии новой формы, если серверных значений ещё нет.

Локальный черновик версии 2 содержит только временные поля прогноза, КТГ, ТО и примечания. Дата и смена по-прежнему не сохраняются. Сброс текущего прогноза не удаляет постоянные пользовательские и технические настройки.

Сводка из формы удалена, поиск перенесён в верхний блок. Без поискового запроса показывается остановленная техника в ремонте, при поиске — любая подходящая техника активного парка независимо от состояния. PDF всегда содержит весь парк. При выборе «Исправен» в текущем PDF скрываются неисправность, начало простоя и плановый выход; сохранённые планы и история ремонта не изменяются. Примечание механика выводится непосредственно после текста заявки, перед курсивной причиной ожидания запчастей.

Порядок групп в форме, PDF и сводке определяется полем `group_car.report_sort_order` (integer NOT NULL DEFAULT 0) по возрастанию. Меньшее число означает более раннюю позицию. При равенстве группы упорядочиваются по имени. API передаёт значение как `vehicle.groupReportSortOrder`. Поле добавляется DatabaseInitializer и отдельной миграцией `scripts/migrations/20261012_group_report_sort_order.sql`. Существующие и новые группы по умолчанию имеют значение 0.

## Показания каждого двигателя

Самосвалы (включая «Карьерный самосвал» и «Автосамосвал») имеют два ДВС, остальная техника — один. API передаёт `vehicle.engineCount`. В форме для каждого ДВС вводятся дата показаний, текущая наработка и моточасы машины при замене этого ДВС. Изменения сохраняются при выходе из поля; ввод наработки создаёт историческую запись.

`vehicle_hour_readings.engine_number`: 1 или 2 для новых показаний каждого ДВС, 0 — прежние записи без указания двигателя. История не переименовывается и не удаляется. Для техники с одним ДВС старые показания однозначно используются для её единственного двигателя. Для самосвалов они показываются в форме как прежние показания без номера ДВС и не присваиваются одному из двух двигателей автоматически. Последние показания выбираются отдельно для каждого двигателя по дате и времени записи.

`vehicle_engine_settings` хранит текущие значения `hours_at_replacement` по паре `(vehicle_id, engine_number)`. `GET /api/gto-settings` возвращает их в engines. `PUT /api/gto-settings/vehicles/{id}/engines/{number}` сохраняет показания и значение при замене, проверяет права механика, число двигателей, неотрицательные значения и дату. Для однодвигательной техники ДВС № 2 запрещён.

В PDF самосвал отображается как 875/852 в наработке и 18225/17900 в колонке «М/ч при замене ДВС». Для одного ДВС — одно число. Пустое значение одного двигателя сохраняет свою позицию: 875/ или /852; если неизвестны оба, ячейка пустая. Данные при замене красные. Значения не суммируются и не пересчитываются автоматически.

Старый CSV-импорт сохраняет прежний формат и работает только с engine_number = 0, поэтому он не перезаписывает новые показания ДВС № 1/№ 2. Для самосвалов такие импортированные значения необходимо уточнять отдельно. Миграция `scripts/migrations/20261012_engine_hours.sql` включена в DatabaseInitializer.
