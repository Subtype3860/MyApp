# Регионы / участки техники

Панель «Регионы / участки и закрепление техники» размещена только в отдельном меню **«Участок»**. Из «Транспорта» и «Пользователей» она убрана.

Доступ к меню и управлению имеют Администратор, Старший механик и Главный механик. Сервер проверяет актуальную роль или профессию в базе при каждом запросе. Они могут создавать, переименовывать и архивировать участки, закреплять и перемещать технику, просматривать историю закреплений и назначать пользователям доступ к участкам.

В этом меню доступен список всей техники для закрепления, включая архивную и незакреплённую. Архивную технику перемещать нельзя. Управленческий список не снимает ограничений по участкам с журналов работ, медиа и отчётов. Данные пользователя для выбора ограничены именем, логином и ролью; редактирование ролей и других прав остаётся в административном разделе.

Архивировать участок с текущей техникой нельзя: сначала её нужно переместить. Удаление участков и записей перемещения не предусмотрено.

## Первичная настройка

1. Открыть отдельное меню «Участок» и создать участки.
2. Выбрать «Без закрепления», открыть «Перемещения» нужной машины и закрепить её за участком.
3. В «Доступ пользователей к участкам» выбрать пользователя, отметить участки и сохранить.
4. В карточке пользователя отдельно настроить права на разделы и действия: просмотр транспорта, ремонт, моточасы, ТО, отчёты.

Администратор видит весь парк, включая архивную и незакреплённую технику. Для остальных отсутствие назначенных участков означает отсутствие доступа к работам и отчётам по технике; управленческий список в меню «Участок» доступен Старшему и Главному механику. Существующий парк автоматически не распределяется. Новая карточка тоже остаётся без участка до закрепления в меню «Участок».

## Перемещение

При переезде закрывается прежний период закрепления и открывается новый. Записываются участок, начало, окончание, автор, время регистрации и примечание. Можно указать фактическое время в прошлом, но оно должно быть позже начала текущего закрепления; будущие перемещения не принимаются. Пустое время означает момент сохранения. Интерфейс показывает время в часовом поясе устройства.

Идентификатор машины не меняется, работы, неисправности, моточасы и медиавложения не копируются и не удаляются. Пользователи нового участка видят **всю историю машины**, включая прежние участки. Пользователи старого участка теряют доступ, если не имеют доступа к новому. История самих перемещений также доступна текущему участку.

Изменения проверяются под транзакционной блокировкой. Клиент передаёт идентификатор текущего закрепления: при устаревшем состоянии возвращается HTTP 409. Уникальный индекс запрещает два открытых периода для одной машины. Начало нового периода совпадает с окончанием предыдущего.

## Серверная защита

На каждом HTTP-запросе сервер читает актуальную роль пользователя, его участки и текущие закрепления. EF Core query filters ограничивают технику, ремонты, моточасы, закупки техники/заявки ЗЧ, настройки ГТО, ТО и медиа. Доступ через прямой идентификатор не обходит фильтр. Билет видеопотока повторно проверяет участки владельца билета. Изменения доступа действуют со следующего запроса без нового входа.

Прогноз ГТО выбирается по участку. Организация и подпись участка берутся из справочника; свободный ввод организации убран. В прогноз и экспорт входят только машины выбранного участка. Снимки, версии, история и черновики разделены по участку, дате и смене. Сервер отклоняет строки техники другого участка. Старые общие снимки сохраняются с пустым идентификатором участка и доступны как резервная версия с фильтрацией по текущим закреплениям; при сохранении создаётся отдельный снимок участка. Права участка не заменяют права на редактирование. Вспомогательные работы без техники и складские справочники не привязываются к участкам этим изменением.

Фоновые задания и инициализация БД не имеют пользовательского ограничения. Для HTTP-запросов область доступа задаётся middleware; анонимные запросы не получают парк. По согласованному правилу сохраняются публичные ссылки на отдельные фото/видео из отчётов: только после проверки подписи конкретного файла контроллер временно снимает ограничение для его чтения. Выдача новых ссылок проверяет участки пользователя. Смена участка не отзывает уже выданную публичную ссылку. Опубликованный контроллер публичных ссылок и интерфейс отчётов восстановлены из архива действующей версии, чтобы сохранить это поведение.

## Хранение и API

`FleetRegionSchema` создаёт таблицы `fleet_regions`, `fleet_region_grants`, `vehicle_region_assignments` в существующем `DatabaseInitializer`. Ручной вариант миграции: `scripts/migrations/20261105_fleet_regions.sql`. Инициализация повторяемая, существующие записи техники не меняет.

- `GET /api/fleet-regions` — доступные участки и признак управления.
- `POST /api/fleet-regions` — создание (Администратор, Старший или Главный механик); `PUT /api/fleet-regions/{id}` — изменение (те же права).
- `GET/PUT /api/fleet-regions/users/{userId}` — доступ пользователя (Администратор, Старший или Главный механик).
- `GET /api/fleet-regions/vehicles` — текущие закрепления доступной техники.
- `GET /api/fleet-regions/vehicles/{vehicleId}/history` — история перемещений.
- `POST /api/fleet-regions/vehicles/{vehicleId}/transfer` — закрепление/перемещение (Администратор, Старший или Главный механик).

Проверки: `FleetRegionPostgreSqlTests`, `FleetReportScopeTests`, `frontend/tests/fleet-regions.spec.js`. PostgreSQL-тесты используют только отдельную базу `*_test` и удаляемые схемы.

Все запросы `/api/gto-reports` принимают обязательный параметр `regionId`. В `gto_reports` добавлен ключ `(region_id, report_date, shift)`; прежние строки сохранены без удаления.

`GET /api/fleet-regions/management` — данные отдельного меню (справочник участков, идентификаторы техники, закрепления и минимальный список пользователей); только для трёх управленческих категорий.
