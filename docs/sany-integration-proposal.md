# Интеграция с SANY SIS (sis-global.sanygroup.com) — предложение

Статус: предложение, код не менялся. Дата: 09.11.2026.

## Что удалось выяснить о портале

Портал — SPA (Vue 2 + Element UI), API — отдельный шлюз:

| Элемент | Значение |
| --- | --- |
| API-шлюз | `https://sis-global.sanygroup.com/api-gateway` |
| Авторизация | `POST /customer/user/onlogin?captchaCode=<код>&language=<язык>`, тело `{ account, password }` |
| Капча | `GET /customer/user/v2/kaptcha.jpg`; идентификатор приходит заголовком `kaptchaid`, клиент отправляет его в `captchaCodeId` |
| Токен | возвращается в `data.token`; далее заголовки `Authorization` и `Authorization-userId` |
| Сессия | `withCredentials: true` — cookies обязательны |
| Поиск техники | `/customer/equipmentInfo/queryByCondition`, `queryByEquipment`, `queryByEquipmentNew`, `queryChildren` |
| Детали и BOM | `/bom-server/agentEquipment/getEquipmentDetail`, `/customer/equipmentInfo/childrenBomPage` |
| Прочее | мануалы (`/bom-server/manual/...`), аналоги и фото деталей (`/bom-server/dimpart*/...`, `/bom-server/materialLink/...`) |

CORS отдаёт `Access-Control-Allow-Origin: *` и `Allow-Credentials: true`; браузерные
запросы с cookies из нашего домена всё равно ненадёжны, поэтому нужен серверный прокси.

Важно: это **каталог запчастей и BOM** по коду техники, а не телеметрия. То есть
интеграция даёт поиск узлов, деталей, номеров и мануалов по equipment code.

## Варианты

### A. Официальный API/партнёрский доступ (целевой)

Запросить у SANY доступ к SIS API или выгрузку каталога. Плюсы: легально, стабильно,
без капчи и хранения паролей. Минусы: сроки зависят от SANY, вероятно NDA и отдельный
договор. Это единственный вариант, который можно считать долговременным.

### B. Серверный шлюз с капчей, которую вводит человек (рекомендуемый пилот)

Наш API работает прокси между интерфейсом и SIS:

```
[Атлас UI] → [Atlas API /api/sany/*] → [sis-global.sanygroup.com/api-gateway]
```

Сценарий:

1. `POST /api/sany/session` — пользователь вводит логин/пароль SANY. Сервер запрашивает
   капчу, сохраняет `kaptchaid` и cookies в изолированной сессии (в памяти, TTL 10–15 минут),
   возвращает изображение капчи и `sessionId`. Пароль живёт только в этой сессии.
2. `POST /api/sany/session/{id}/login { captchaCode }` — сервер отправляет `onlogin`
   с сохранёнными cookies, получает `token`, сохраняет его зашифрованным (TTL = срок
   токена), пароль сразу стирает.
3. `GET /api/sany/equipment?code=ET150SE30008` — прокси-запрос
   `queryByCondition`/`queryByEquipment`; результат кешируется на 5–10 минут.
4. `GET /api/sany/equipment/{code}/bom` — дерево узлов и деталей, номера, фото.
5. Когда токен истёк — сессия помечается «нужна капча», интерфейс снова показывает
   картинку и поле ввода. Автоматического обхода капчи нет.

Плюсы: работает уже сегодня, пароль не хранится, никакой OCR капчи не требуется.
Минусы: капча требуется при каждом входе/истечении токена; зависимость от вёрстки и
эндпоинтов портала; нужна проверка, что условия использования SIS допускают такой
доступ; при смене API интеграция ломается.

### C. Ручной переход без интеграции

Кнопка «Открыть SIS» с подстановкой кода техники в буфер обмена и списком кодов.
Плюсы: ноль рисков и работ. Минусы: нет автоматизации, данные не попадают в Атлас.

## Рекомендация

1. Сразу направить запрос в SANY на официальный доступ (вариант A) — это снимает
   вопрос легальности и капчи.
2. Параллельно сделать пилот варианта B за флагом функции и только для согласованного
   круга пользователей, пока нет ответа SANY.
3. Вариант C — временная заглушка, если ответ SANY затянется.

## Что нужно от вас

- Подтверждение, что доступ к SIS через стороннее приложение не нарушает договор
  с SANY (лучше письменное согласие).
- Список кодов техники и сопоставление с парком Атласа (например, `ET150SE30008` —
  самосвал, `SY1204CD00728` — экскаватор). Предлагаю хранить связь
  `vehicle.sany_equipment_code`.
- Какие данные нужны в Атласе: только поиск деталей и номеров, или ещё BOM-дерево,
  мануалы и фото.
- Нужно ли сохранять сессию между перезапусками браузера (тогда токен хранится
  зашифрованным на сервере, а не только в памяти).

## Безопасность и правовые ограничения

- **Пароль SANY уже был отправлен в чат — смените его** и не переиспользуйте с другими
  сервисами. В коде и репозитории пароль храниться не будет.
- Пароли и токены SIS не пишем в БД и логи; сессия — в памяти процесса, токен —
  зашифрованным, TTL ограничен; выход и истечение всё стирают.
- Капча решается только человеком. Попытки OCR/обхода — риск блокировки аккаунта и
  нарушения условий портала.
- Прокси ограничиваем правами Атласа (например, `vehicles.parts_request`), добавляем
  rate limit, журнал запросов и маскирование секретов.
- Ошибки SIS (401/429/HTML вместо JSON) не должны раскрывать содержимое ответа
  пользователю и не должны валить наши запросы.

## Оценка работ (вариант B)

| Работа | Оценка |
| --- | --- |
| Серверный прокси: сессия, капча, логин, кеш, ошибки | 2–3 дня |
| Эндпоинты поиска техники и BOM, сопоставление с парком | 1–2 дня |
| Интерфейс: подключение SIS, ввод капчи, поиск, карточка деталей | 2 дня |
| Тесты (юнит + браузерные с моками SIS) | 1 день |
| Документация и инструкция администратора | 0,5 дня |

Вариант A после получения доступа: 3–5 дней на интеграцию без капчи и хранения паролей.
