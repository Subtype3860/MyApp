# Импорт CSV / Excel и транзакционные остатки

PostgreSQL — источник истины. CSV и XLSX служат для загрузки и выгрузки; имя загружаемого файла произвольное. В интерфейсе выбирается источник: склад (`warehouse`), остатки механиков (`mechanics`) или работники (`workers`). Для XLSX выбирается лист. Старые маршруты `csv-files/o.csv`, `c.csv`, `p.csv` сохранены для совместимости; новый маршрут — `api/admin/imports/{source}`.

## Полный снимок остатков

Каждый импорт склада или остатков механиков — полный снимок только выбранного источника. Указанные позиции получают абсолютное количество из файла. Отсутствующие позиции сохраняются с количеством **0**; их ID и история не удаляются. Работники добавляются и обновляются, отсутствующие работники сохраняются.

Перед сохранением приложение проверяет весь файл и показывает первые 10 строк, количество добавлений, обновлений и обнулений. Предпросмотр не записывает данные. При сохранении проверка повторяется; окончательная статистика отражает состояние на момент транзакции, поэтому может отличаться от предпросмотра при параллельных операциях.

Пустые файлы, файлы только с заголовками, отрицательные или некорректные количества, дубликаты позиций, пустые обязательные поля и повреждённый формат отклоняют весь импорт. Пустой файл не обнуляет склад. Импорт, обнуление отсутствующих позиций, метаданные и журнал фиксируются одной транзакцией.

## Идентичность записей

`app_stock_balances.id` и `app_csv_workers.id` — UUID и первичные ключи. Экспорт CSV содержит колонку `ID`. Если ID указан, он должен принадлежать существующей записи выбранного источника. Это позволяет переименовать запись без смены ID. Для новой записи ID оставляют пустым; он создаётся в базе.

Для файлов без ID остаётся совместимое сопоставление: материалы по наименованию (пробелы по краям удаляются, регистр сохраняется), работники по полному ФИО. Наименование уникально внутри склада, но ФИО не является уникальным ключом. Полное ФИО вычисляется из last_name, first_name, patronymic; отдельный столбец full_name в app_csv_workers не хранится. При нескольких работниках с одинаковым ФИО требуется ID из выгрузки. Для сопоставления сторонних файлов после переименования в будущем следует добавить код материала / табельный номер: внутренний UUID сам по себе не позволяет распознать такие изменения.

Текущие документы и группы материалов ещё ссылаются на наименования, подписи — на части ФИО. Добавление ID не переписывает исторические документы. Переименование через импорт сохраняет ID самой позиции, но не переименовывает эти внешние ссылки автоматически; их переход на связи по ID — отдельная миграция.

## Форматы

Требуются заголовки. CSV: UTF-8, разделитель `;`, `,` или табуляция, CSV-кавычки и десятичная запятая. XLSX: значения выбранного листа передаются в тот же валидатор, что и CSV. Формулы читаются по сохранённым Excel результатам, приложение их не вычисляет. Старый бинарный XLS не поддерживается.

Остатки: `Наименование;Ед.изм.;Количество` либо `name;unit;amount` / `quantity`. Работники: `LastName;FirstName;Patronymic;Profession` либо `ФИО;Профессия`. Колонка `ID` необязательна. Подписи задаются отдельно, колонка `Роспись` в импортируемом файле не допускается.

Дополнительные колонки сохраняются в JSONB. Их отсутствие в следующем файле не удаляет прежние значения; правило полного снимка относится к количеству. Лимиты: 20 МБ, 100000 записей, 80 колонок, 16384 символа в поле. Для XLSX также ограничен размер распакованных данных (100 МБ).

## Служебные таблицы и миграция

- `app_import_sources`: описание источника (`source_key`), колонки выгрузки и время последнего импорта. Заменяет `app_csv_sources` с сохранением метаданных.
- `app_import_history`: UUID загрузки, источник, время и фактические количества добавлений, обновлений, обнулений.
- `app_schema_migrations`: завершённые переходы схемы. Маркер `legacy_csv_bootstrap_v1` предотвращает повторную загрузку старых представлений.

Первичный перенос старых `v_full_ost`, `v_meh_ost`, `v_workers` / `employees` выполняется один раз. Отрицательные и пустые старые остатки становятся нулевыми. Одинаковые позиции с одинаковыми единицами и дополнительными полями суммируются до обнуления отрицательной суммы. Противоречивые дубликаты отклоняют миграцию. Эти послабления не применяются к новым пользовательским файлам.

Первичный перенос использует временную таблицу `csv_bootstrap_snapshot`, которая удаляется при commit. Постоянная `app_csv_migration_snapshots` больше не создаётся. Старые таблицы снимков удаляются отдельным скриптом `20261013_remove_obsolete_snapshots.sql` после проверенной резервной выгрузки; удаление без CASCADE остановится при неожиданных зависимостях. Выгрузки хранятся в игнорируемой Git папке `.local-backups`.

Старые внешние представления и физические CSV не изменяются. Актуальные данные скачиваются из API. Откат только бинарников на старую версию после новых списаний небезопасен: старые CSV уже не отражают состояние базы.

## Конкурентные операции

Импорт, списание и восстановление используют общую transaction-scoped advisory lock на выбранный склад. Остатки при списании читаются с FOR UPDATE. Списание проверяет реальный баланс базы. Ошибка или отмена до commit откатывает все изменения. При удалении требования восстановление и удаление документа также выполняются одной транзакцией.

## Проверки

Модульные тесты проверяют CSV / XLSX, выбор листа, UUID, ошибки и пустой снимок. PostgreSQL-тесты проверяют полный снимок, сохранение ID при переименовании, изоляцию складов, атомарность, журнал, первичный перенос и повторный запуск. Интеграционные тесты выполняются только в отдельной одноразовой базе с именем `*_test`.
