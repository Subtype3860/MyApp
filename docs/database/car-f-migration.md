# car_f: перенос из CSV в PostgreSQL

11.10.2026 по запросу пользователя public.car_f перенесена из file_fdw в обычную таблицу базы job. Все 39 записей и исходные значения ID сохранены и проверены по снимку. Имена, порядок, типы и ограничения длины столбцов сохранены, включая исторические названия gor_numder и vim.

Добавлены первичный ключ id и GENERATED BY DEFAULT AS IDENTITY. После переноса последовательность выставлена на 39; следующая автоматически добавленная запись получает ID 40.

Сохранены:

- public.car_f_external_20261011 — исходная внешняя таблица, читающая /mnt/shara/data/car.csv;
- public.car_f_snapshot_20261011 — материальный снимок 39 исходных записей;
- локальная проверенная копия данных, исходное определение и SQL восстановления в .local-backups/car_f/20261011T042900Z (исключены из Git).

Скрипт: scripts/migrations/20261011_car_f_to_local.sql. Выполнен внутри явной транзакции. До применения проверен на отдельной схеме с копией внешней таблицы: перенос, следующий ID, INSERT, UPDATE, DELETE; вся проверочная транзакция откатилась. Затем перенос применён к public и подтверждён новым подключением.

Скрипт не перезаписывает уже перенесённую обычную таблицу. При занятых резервных именах, зависимостях, пустых/повторяющихся ID или несовпадении снимка перенос прекращается. Проверка контрольной суммы подготовленного снимка передаётся через локальное значение myapp.car_f_expected_fingerprint. При запуске вручную необходим BEGIN/COMMIT и предварительная резервная копия.

«Парк техники» приложения использует GET /api/vehicles и таблицы number_car, model_car, type_car, group_car. car_f в этом запросе не участвует. Перенос car_f не синхронизирует её с number_car; CRUD-редактор и такая синхронизация в рамках этого переноса не добавлялись. История ремонтов привязана к UUID number_car.id, а не к целому car_f.id.

Откат после проверки новых зависимостей: внутри транзакции переименовать обычную car_f в отдельное резервное имя и вернуть внешней car_f_external_20261011 имя car_f. Не удалять обычную таблицу, если в ней уже появились новые записи. Если исходный CSV изменился, для восстановления точных старых значений использовать материальный снимок или локальный restore-snapshot.sql.

## Последующее удаление

По отдельному явному запросу пользователя 11.10.2026 обычная public.car_f удалена. Перед удалением заново экспортированы все 39 текущих строк, проверен SHA-256 и создан public.car_f_removed_snapshot_20261011. DROP выполнен без CASCADE внутри транзакции после сверки снимка и исходных данных. Сохранены прежние резервные снимки и исходная внешняя таблица. Парк number_car остаётся отдельным источником данных.

Скрипт удаления: scripts/migrations/20261011_remove_unused_car_f.sql. Локальная копия до удаления хранится под .local-backups/car_f/before-delete-* и исключена из Git. Предыдущие разделы этого документа описывают историю переноса, а не текущую доступность car_f.
