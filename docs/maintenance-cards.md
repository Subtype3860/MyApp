# Электронные карты ТО

Путь: **Транспорт → Проведение ТО → выбрать технику → Карты ТО**.

## Подготовка

В библиотеку включены 17 неопубликованных шаблонов:

- SANY SET150S: 150, 350, 700, 1000, 2000, 3000, 4000.
- SANY SY1250H: 250, 500, 1000, 2000, 4000.
- KOMATSU D375А-6: 250, 500, 1000, 2000, 4000. Это бульдозер из отдельного листа второго файла.

Источники: `Карта ТО_SANY SЕT150S.xlsx` и `Карта ТО 933_91_91_98.xlsx`.
Личные данные, показания и даты из шапок не входят в шаблоны. Строки работ и материалов
сохраняют исходные формулировки, включая требующие проверки опечатки и неоднозначности.
Количество строк не является подтверждением технической корректности регламента.

Механик открывает библиотеку, проверяет модель (как она указана в парке), вид ТО,
операции, нормы, единицы, условные замены и заключительные проверки, затем утверждает шаблон.
У листов SET150S «ТО-150» и «ТО-3000» заголовок ТО-2000; они намеренно не опубликованы.
350 и 700 получены из общего листа, применимость каждого нужно проверить отдельно.
В карте KOMATSU количество без единиц оставлено в тексте операции; расходные материалы
и заключительный контроль нужно настроить вручную. Пустая норма отличается от нуля.

Редактор позволяет добавлять/удалять операции и выбирать источник материалов из
«Технического обслуживания», указывать агрегат, ДВС или
сторону в поле «Агрегат / ДВС». Для раздельного результата двух ДВС создаются две операции.
Подбор карты использует модель и вид ТО, игнорируя регистр, пробелы и знаки пунктуации.
Нельзя автоматически подбирать по одному гаражному номеру или похожему названию модели.

## Выполнение

1. Создать карту из опубликованного шаблона для следующего шага графика.
2. Указать даты, показания, водителя, марку ДВС и исполнителей. Моточасы берутся из
   существующего журнала на дату ТО; расчётные значения обозначены отдельно.
3. В строке операции: описание → медиа выполнения → чекбокс «Выполнено» и ФИО.
   При отметке пустое ФИО заполняется текущим пользователем или указанным общим исполнителем.
   Уже указанный исполнитель сохраняется; снятие галочки не удаляет ФИО и вложения.
   Причины пропусков, состояние узла и замеры доступны в раскрывающемся блоке.
   Материалы по факту заполняются отдельно. При вводе факта (включая ноль) пустое поле
   исполнителя заполняется ФИО текущего пользователя. Указанное ранее ФИО не заменяется.
   Поле «Использованный аналог» убрано из формы и печатной таблицы; старые данные
   остаются в сохранённых записях.
4. При необходимости прикрепить фото JPEG/PNG до 4 МБ или видео MP4/WebM до 25 МБ
   (до 20 файлов на карту), открыть их для просмотра внутри карты, создать связанную
   заявку о дефекте без остановки техники. Остановку оформлять в журнале ремонта.
5. Передать карту на проверку. Все строки должны быть заполнены, обязательные
   заключительные проверки — выполнены. У материалов указывается расход, включая ноль.
6. Механик принимает или возвращает карту с причиной. При невыполненных работах или
   дефектах для приёмки обязательно решение механика. Это не закрывает связанные дефекты.

Статусы: черновик → на проверке → принята; на проверке → черновик при возврате.
Черновик можно отменить с причиной. Принятая карта доступна только для чтения.
История содержит снимки заполнения, автора и время изменений. Исполнители строк
указываются текстом; это не квалифицированная электронная подпись.

Время работ и простой рассчитываются отдельно. «Печать / PDF» открывает печатную форму
для системного диалога печати. Моточасы принятой карты зафиксированы и не пересчитываются.

### Печатная форма

Печатная форма повторяет бланк «Техническое обслуживание» из исходных карт Excel
(`Карта ТО 933_91_91_98.xlsx`, `Карта ТО_SANY SЕT150S.xlsx`): A4, книжная ориентация,
заголовок «Техническое обслуживание <модель> <вид ТО> от <дата>», таблица шапки
(№ шасси, модель ТС, марка ДВС, пробег, наработка, время остановки и запуска, простой,
ФИО водителя), операции с отметками ДА/НЕТ, причина невыполнения и исполнитель,
раздел «Замена смазочных и расходных материалов» с таблицами «Смазывающие» и «Фильтры»,
чек-лист, примечание и подписи ответственных.

Операции с несколькими вложениями: название операции становится ссылкой на первый файл,
остальные отмечены надстрочными номерами. Ссылки подписанные и постоянные:
`POST /api/maintenance-plans/cards/{id}/media-links` выдаёт их в пределах доступных
пользователю машин, `GET /api/maintenance-plans/cards/{id}/media/{photoId}/{signature}`
отдаёт только этот файл без токена (заголовки `no-store`, `noindex`). Подпись привязана
к паре «карта — вложение»; выдача ссылок не расширяет доступ к другим картам и медиа.

Материалы делятся по справочнику «Группы материалов» (`GET /api/material-groups/map`
для `v_full_ost`, сопоставление по названию без учёта регистра и лишних пробелов).
В «Смазывающие» попадают нефтепродукты — материалы группы, в названии которой есть
«Нефтепродукты»; всё остальное, включая материалы без группы, выводится в «Фильтрах».
Если справочник недоступен, печать не прерывается: все материалы попадают в «Фильтры».

Наработка моточасов в шапке записывается по каждому ДВС полем из пяти символов через
« / » (например, `20207 / 14752`). Если на дату ТО показаний в журнале нет, значение
рассчитывается и помечается звёздочкой со сноской под шапкой.

## Материалы и склад

Единый источник материалов — существующий раздел «Техническое обслуживание»
(оборудование → вид ТО → материалы и нормы). Список из Excel больше не используется
при создании новых карт. Редактировать его отдельно в библиотеке карт не нужно.

При создании карты сервер подбирает источник сначала по точной модели, затем по типу
техники (например, Самосвал / Карьерный самосвал → Самосвалы) и виду ТО. При неоднозначности требуется
выбрать «Источник материалов» в редакторе шаблона. Явная привязка проверяется на
соответствие виду ТО. Количество берётся из нормы технического обслуживания, даже
если на складе нулевой остаток; единица — из существующего сопоставления со складом.

В карте сохраняются идентификатор источника, его название и снимок норм. Изменение
настроек применяется к новым картам; уже заполненные карты не пересчитываются.
В старом черновике доступна кнопка «Загрузить материалы из технического обслуживания».
Она доступна до ввода фактического расхода и аналогов; сервер также проверяет это
условие и версию карты. Выполненные работы и медиа сохраняются. Пустой настроенный
интервал означает пустой список материалов, а отсутствующий источник — ошибку подбора.

«Подготовить требование по нормам» сопоставляет материалы сохранённой карты с остатками
по точному названию и единице. Пользователь видит несовпадения и дефицит, затем явно
заменяет выбранные компоненты доступными материалами. Неоднозначные позиции добавляются
вручную на складе. Формирование требования использует существующий экран и не изменяет
расход карты. Автоматического списания, резервирования и обратной связи номера
требования с картой нет.

## Сохранение и права

- Право заполнения: `vehicles.maintenance_execution` либо существующее право управления парком.
- Шаблоны и приёмка: существующее право управления парком (механики/администраторы).
- Доступ к картам ограничен доступными пользователю машинами через фильтр регионов.
- Автосохранение через 1,2 с; локальная копия черновика привязана к пользователю и карте.
- При потере связи введённое остаётся на устройстве. После открытия карты можно восстановить
  локальную копию той же версии. При конфликте версии доступен просмотр локальных данных
  и ручной перенос изменений; молчаливого объединения или перезаписи нет.
- Полного автономного запуска веб-приложения и нативного экрана Android пока нет.
- Фото, дефекты, создание, отправка и приёмка требуют подключения.

## Хранение и графики

`MaintenancePlanSchema.EnsureAsync` создаёт таблицы карт и загружает отсутствующие seed ID.
Повторный запуск не перезаписывает отредактированные шаблоны. В карте хранится независимый
снимок версии шаблона. Медиа хранятся в PostgreSQL с ограничением размера. Существующие фото и адреса API
сохранены. Тип определяется по содержимому файла, а не только по MIME из браузера.

Приёмка использует ту же блокировку машины и транзакцию, что завершение планового ТО:
проверка версий, фиксация карты, событие истории и следующий шаг сохраняются вместе.
Идентификатор карты служит идентификатором операции завершения. Повтор принятия с тем же
решением возвращает прежний результат; другой запрос с тем же ID отклоняется.
Обычное завершение через старый экран/API заблокировано при наличии активной карты.
Изменение графика после начала карты вызывает конфликт при приёмке; карту нужно вернуть,
отменить и создать по актуальному графику, сохранив старую в истории.

Стандартные циклы 350–4000 и 250–4000 используют ТО-1000 на отметке 3000.
При запуске сервера исправляются только точные совпадения прежних стандартных циклов.
Интервалы, следующий индекс, прошлое ТО, моточасы и обкатки сохраняются. Исправление
создаёт отдельное событие версии. Ранее сохранённые события не переписываются.
Автором технической записи остаётся последний редактор графика; текст отмечает миграцию.
Пользовательские циклы не меняются. Приёмка обкаточного ТО не сдвигает основной цикл.

## Проверки

`MaintenanceCardRulesTests`: пропуски, обязательный контроль, дефект после выполненной
проверки, нулевой/отсутствующий расход, время, состав карты, библиотека и повтор ТО-1000.
`maintenance-cards.spec.js`: заполнение, конфликт, локальное сохранение и приёмка на
390/1440 px. `maintenance-planner.spec.js`: существующее планирование и исправленный цикл.
`MaintenanceCardPersistenceTests`: интеграционные сценарии PostgreSQL (требуют
`MYAPP_TEST_POSTGRES` с отдельной базой, имя которой оканчивается на `_test`).

### Доступ к библиотеке и компактный редактор

Раздел «Проведение ТО» разделён на подменю: «ТО по картам» (заполнение и приёмка карт),
«График и история» и «Библиотека шаблонов». Первое доступно всем, у кого есть право
заполнения; остальные два видны только механикам. Флаги `canManage` и `canUseLibrary`
возвращает `GET /api/maintenance-plans`, поэтому подменю не показывается без прав.
История графика (`GET /api/maintenance-plans/{vehicleId}/history`) требует `canManage`
и возвращает 403 остальным; сохранение графика и регистрация выполнения проверяли это
и раньше.

Библиотеку шаблонов могут просматривать, редактировать и утверждать сотрудники профессий «Механик», «Старший механик», «Главный механик», «Инженер ППР». Профессия проверяется на сервере по учётной записи. Роль администратора сама по себе не даёт этого допуска. Чтение и сохранение полной библиотеки через card-templates возвращает 403 остальным профессиям. Для начала ТО card-template-options возвращает только опубликованные варианты (идентификатор, версия, модель, вид ТО и источник); заполнение карт остаётся доступным по существующим правам.

Поле «Агрегат / ДВС» убрано из редактора операций. Ранее сохранённое значение остаётся в данных. Библиотека и редактор используют компактные отступы, короткие кнопки и строки операций; на узком экране поля располагаются вертикально.
