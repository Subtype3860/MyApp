# Release 20261108-3accd21

Published to https://boora.ru/ on 2026-11-08 (Asia/Sakhalin). Commit `3accd21`,
branch `refactor/integration-deepseek`.

## Changes

- Карты ТО: печатная форма повторяет бланк «Техническое обслуживание» из исходных
  карт Excel (шапка, ДА/НЕТ, причина, исполнитель, «Смазывающие»/«Фильтры», чек-лист,
  подписи). Название операции со вложениями стало ссылкой на первый файл; остальные
  вложения отмечены надстрочными номерами.
- Новые эндпоинты: `POST /api/maintenance-plans/cards/{id}/media-links` и публичный
  `GET /api/maintenance-plans/cards/{id}/media/{photoId}/{signature}` с HMAC-подписью
  на пару «карта — вложение».
- Наработка моточасов в шапке печати — в формате `xxxxx / xxxxx`; расчётные значения
  помечаются звёздочкой и сноской.
- Материалы делятся по справочнику «Группы материалов»: «Смазывающие» — группы со
  словом «Нефтепродукты», «Фильтры» — всё остальное.
- Вход: чекбокс «Запомнить меня» (localStorage или sessionStorage для вкладки).
- ГТО: убрана кнопка «Открыть отчёт», выбор в списке истории открывает отчёт сразу;
  разметка раздела уплотнена.
- Исправлена политика `reports.shift`: `POST /api/report-media/links` отвечал 500
  («The AuthorizationPolicy named: 'reports.shift' was not found»).
- В релиз вошла незакоммиченная работа ветки: доступ по профессиям, оформление
  отчёта за смену, правки карт ТО и вспомогательных работ.

## Known issue

NAS `//10.8.8.2/shara` (`/mnt/dietpi`) недоступен с сервера: `Host is down`,
ping 10.8.8.2 — 100% потерь. `StagedMediaTransferService` не может перенести файлы из
`/opt/myapp/media-staging` в постоянное хранилище и пишет ошибку каждые 10 секунд.
Проблема инфраструктурная и не связана с релизом: БД (10.8.8.8) доступна, API работает.
После восстановления NAS фоновая служба должна забрать накопленные файлы сама.
